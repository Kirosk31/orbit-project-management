# Public site (`apps/site`)

The marketing site is a separate Next.js App Router workspace. The product stays a Vite single-page
application behind login; the public pages move to Next.js because they need what an SPA does badly:
HTML that is complete before JavaScript runs, per-language URLs, and real metadata for search engines
and link previews.

## Why two apps

| Concern   | `apps/web` (Vite SPA)           | `apps/site` (Next.js)                        |
| --------- | ------------------------------- | -------------------------------------------- |
| Audience  | Signed-in teams, hours per day  | Visitors and crawlers, one visit             |
| Rendering | Client, behind authentication   | Static HTML per locale (SSG)                 |
| Data      | Live API, Socket.IO             | None at request time                         |
| SEO       | Not needed                      | `hreflang`, canonical, sitemap, Open Graph   |
| Deploy    | NGINX container next to the API | Vercel, Azure Static Web Apps or App Service |

Both apps draw from the same workspace packages, so the brand cannot drift:

- `@orbit/design-tokens`: the Azulejo OKLCH tokens, both themes and the Tailwind v4 mapping
- `@orbit/locales`: the English, Spanish, French and Brazilian Portuguese catalogs
- `@orbit/brand`: the logo and the tile progress panel

## Routes

- `/` → `proxy.ts` negotiates `Accept-Language` and redirects to a locale (`es-CR` first for
  Costa Rican browsers, then base language, then `es`).
- `/es-CR`, `/es`, `/pt-BR`, `/en`, `/fr`: prerendered at build time (`generateStaticParams`,
  `dynamicParams = false`). Costa Rica shares the Spanish catalog with its own `lang`, `hreflang`
  and `og:locale`.
- `/{locale}/opengraph-image`: 1200×630 PNG generated by `next/og` at build time, with Archivo
  vendored under `assets/fonts` (SIL OFL).
- `/sitemap.xml` and `/robots.txt`: metadata routes; every sitemap entry lists all alternates.

## Interactivity budget

Only two client components ship JavaScript: the live board in the hero (the card that lands in Done
and glazes its tile, with a replay button) and the theme toggle. The FAQ, the language menu and the
mobile navigation are native `<details>` elements, so they work without JavaScript.

The theme is applied before first paint by `/theme-init.js`, an external file rather than an
inline script, and uses the same `orbit.theme` storage shape as the app.

## Security headers

`next.config.ts` sends a Content-Security-Policy plus `nosniff`, a referrer policy and a
permissions policy. Statically rendered Next.js pages embed an inline bootstrap script, so
`script-src` must allow `'unsafe-inline'`; nonces would force every page to render dynamically.
The site holds no sessions or user data, which keeps that trade-off acceptable. The app keeps its
stricter `script-src 'self'` policy.

## Configuration

| Variable               | Default                 | Purpose                                   |
| ---------------------- | ----------------------- | ----------------------------------------- |
| `NEXT_PUBLIC_SITE_URL` | `http://localhost:3000` | Canonical origin for metadata and sitemap |
| `NEXT_PUBLIC_APP_URL`  | `http://localhost:5173` | Where sign-up and sign-in links point     |

Both are read at build time.

## Commands

```bash
npm run dev -w @orbit/site        # http://localhost:3000
npm run build -w @orbit/site      # static pages, OG images, sitemap
npm run test -w @orbit/site       # Vitest: locale negotiation, dictionaries, alternates
npm run test:e2e -w @orbit/site   # Playwright + Axe against the production build
```

## Deploying

- **Vercel:** import the repository, set the root directory to `apps/site`, add both variables.
- **Azure Static Web Apps:** app location `apps/site`, output handled by the Next.js hybrid
  support; the locale redirect in `proxy.ts` needs the hybrid (not static export) mode.
- **Azure App Service or a container:** `npm run build -w @orbit/site` then
  `npm run start -w @orbit/site` behind TLS.

CI builds, type-checks and tests the site in both GitHub Actions and Azure Pipelines, and runs its
Playwright and Axe smoke tests in the browser stage.
